# 學習精靈（英文單字×寵物戰棋）｜Product Brief

2026-11-18（v3：寵物、對戰、學習獎勵的主要規則已決定）

## 產品概要

學習精靈是一個英文單字的桌面小程式。使用者能在電腦桌面上看到自己養的精靈寵物（最多 6 隻），多的寵物放在倉庫裡。使用者做單字題，就能孵化、餵養、進化寵物；寵物組成 6 隻的隊伍，在六角格棋盤（以視窗方式開啟）上和其他玩家的隊伍自動對戰。系統記錄使用者看過的每個單字，自行訓練的 AI 模型預測哪些字快忘了，安排錯題練習和每日抽考。

本專題是課程的六人團隊專題，期間 11/27–1/21，最後以本機展示；發表當天有企業媒合。

## 要解決的問題與目標使用者

目標使用者是一般想背單字的人。他們遇到三個問題：

- 背單字枯燥，容易半途而廢
- 背過的字幾天後就忘，也不知道該複習哪些
- 答錯的字沒有被系統化地拿回來練

## 產品目標與核心價值

讓使用者因為想養寵物、想贏對戰而持續背單字，並把時間花在快忘記的字上。

- **寵物養成**：答對題目，桌面上的寵物就獲得經驗值、升級、進化；做題時有機率掉蛋，單字類別決定蛋的屬性
- **桌面寵物**：最多 6 隻寵物住在桌面上，提醒做題；寵物身上出現符號時，代表有額外的複習題；其餘寵物放在倉庫
- **自走棋對戰**：6 隻寵物在六角格棋盤上自動移動、攻擊、施放各自的技能；玩家只負責戰前排陣；組員之間有排行榜
- **學習核心**：錯題題庫、依熟練度換題型、每日抽考
- **AI 預測遺忘**：模型預測答對機率，決定抽考和錯題的順序

## 設計依據

- 遊戲化對學習有小到中等的正面效果；加入故事與社交元素時效果更好（Sailer & Homner, 2020）
- 競技：證據最強，有競賽的遊戲式學習效果量 g = 0.386，在語言和策略類遊戲有效（Chen, Shih & Law, 2020）；英文單字實驗中，有競賽的班單字成績和動機都較好（Liu 等人, 2022）
- 養成寵物：中央大學 My-Pet 研究發現寵物讓學習更有趣，但單靠寵物不會學得更多，加上競賽才讓學習進步更多，所以本產品同時有養成與對戰
- 社交：Duolingo 有好友連續紀錄的使用者，完成每日課程的機率高 22%（相關，非因果）
- 限制：沒有研究直接測過寵物＋競技＋社交的組合，且競賽可能增加焦慮，所以採非同步對戰並自行實驗量化
- 詳見「05-考據與量化.md」

## 已決定的範圍

### 學習

| 功能 | 內容 |
| --- | --- |
| 單字表 | NGSL，MVP 先做詞頻最高的 300 字 |
| 題型 | 英選中、中選英、拼字、例句填空；依熟練度由易到難換題型 |
| 出題方式 | 選項、填空、拼字提示由程式依單字資料自動產生；例句填空每次隨機抽一句、誘答選項每次重抽，讓使用者無法死背題目 |
| 例句來源 | 以 AI 產生為主：開源模型在本機事先產生每字 5 句例句與繁體中文翻譯，經自動檢查與人工檢查後存進題庫；不足的用 Tatoeba 例句庫（CC BY 2.0 FR，需標示出處）補充，再不夠由組員自己寫 |
| 單字紀錄 | 以「字」為單位，記錄每個看過的字的次數、對錯、上次看到的時間 |
| 錯題題庫 | 答錯 1 次進入，答對 1 次移出，再答錯會回來 |
| 強制練錯題 | 答錯累積 5 題時觸發，練 5 題錯題後就能回到一般練習 |
| 桌面練習視窗 | 桌面上有一個做題視窗，可以一直連續做題 |
| 寵物的額外題目 | 桌面寵物身上出現符號時，點擊後做 5 題額外題目，題目是使用者以前看過的單字；這是獨立於每日抽考的複習機制，一天最多出現 4 次、間隔至少 2 小時；獎勵和抽考一樣較多、不計入每日上限，但每天次數有限 |
| 隨機抽考 | 每天第一次登入時一次，每次 10 題，抽考過去答對過、快忘的字；可以延後，不能跳過 |
| 答錯時 | 只顯示正確答案 |
| 拼字題 | 只算第一次送出 |

### 學習獎勵

| 項目 | 內容 |
| --- | --- |
| 等級 | 只有寵物有等級，玩家沒有 |
| 經驗值來源 | 練習任何題型，答對後桌面上的每隻寵物都獲得全額經驗值 |
| 點數 | 選擇題答對 10 點、拼字答對 15 點 |
| 每日上限 | 每天 300 點；抽考的經驗值不計入上限 |

### 寵物

| 功能 | 內容 |
| --- | --- |
| 屬性 | 5 種：食物、自然（動植物、天氣）、身體與健康、生活（家居、物品）、社會與工作；動詞和形容詞歸「通用」 |
| 寵物種類 | 每種屬性 2 種，加上通用，共約 12 種；全部原創，不使用寶可夢或其他既有角色；由團隊自行設計 |
| 進化 | 3 階段；寵物升到進化等級（第 2 階段 Lv.16、第 3 階段 Lv.36，等級上限 Lv.50）時開放「進化挑戰」，做 5 題該寵物同屬性的單字、全部答對才進化，失敗可以再挑戰 |
| 數值 | 同一種寵物基本數值相同，每隻另有 ±10% 的隨機個體差異 |
| 掉蛋 | 每答對一題有 5% 機率掉蛋；答對哪一類單字，就掉那一類的蛋 |
| 孵化 | 拿到蛋後再答對 10 題才孵化 |
| 心情 | 太久沒練習，寵物會不開心；只影響表情和對話，不影響對戰 |
| 桌面與倉庫 | 桌面上最多 6 隻，其餘放在倉庫；桌面上的 6 隻就是對戰隊伍 |
| 圖 | 使用 AI 生成圖（課程允許）；工具待團隊討論，選定後確認其使用條款，並固定提示詞以統一風格 |

### 對戰

| 功能 | 內容 |
| --- | --- |
| 形式 | 非同步：和其他玩家的隊伍對戰，伺服器自動算完，再以視窗播放 |
| 棋盤 | 簡化版戰棋：六角格棋盤，6 對 6，寵物自動移動、找目標、近戰或遠程攻擊；戰前排陣 |
| 技能 | 每隻寵物有獨有技能，以固定冷卻時間施放；技能由共用的效果模組（傷害、範圍、治療、護盾、控制、強化）加參數組成 |
| 技能強度 | 隨玩家在該屬性類別學會的單字數提升 |
| 羈絆 | 同屬性湊 2 隻、3 隻各有一階加成 |
| 隊伍人數 | 不滿 6 隻也能出戰 |
| 場數 | 每天 3 場；另外每答對 10 題換 1 場，每天最多再換 3 場 |
| 獎勵 | 排行榜分數，加上少量寵物經驗值 |
| 決策點 | 12/31：戰棋的移動、找路、技能如果還不穩，就退回固定站位，或改成同屬性共用技能 |
| 不做 | 商店、金幣、裝備、即時連線對戰 |

### 平台與 AI

| 項目 | 內容 |
| --- | --- |
| 形式 | 桌面小程式（Windows），本機執行 |
| 架構 | PySide6 負責桌面寵物、視窗、系統匣；做題、倉庫、對戰棋盤等視窗內嵌網頁（QWebEngineView）；網頁由本機 Flask 提供，介面用 HTML/CSS/JavaScript，對戰動畫用 Canvas |
| 對戰伺服器 | Flask，4 個 API：上傳隊伍、找對手、算戰鬥、排行榜；戰鬥在伺服器上算，避免作弊 |
| 伺服器位置 | 開發期（第 1–4 週）放在開發者的電腦；第 5 週部署到免費雲端平台，讓測試者在家也能對戰；發表當天用雲端版本，並以一台電腦當伺服器＋手機熱點作為備案 |
| 實驗資料收集 | 測試者同意後，匿名作答紀錄上傳到伺服器，用於分析 |
| AI 模型 | 預測使用者這次會不會答對某個字；主模型 Logistic Regression，以隨機森林或梯度提升對照，並和基準比較 |
| 訓練資料 | Duolingo 公開資料集（非商用授權），第 1 週就能開始 |
| 出題 AI | 開源模型用 Ollama 在本機執行，事先產生例句（每字 5 句）；免費、不需要網路與 API 金鑰；做題時不呼叫模型 |
| 有時間再做 | 點單字發音、聽發音選單字題 |

## 主要風險與備案

| 風險 | 備案 |
| --- | --- |
| 戰棋（移動、找路、技能）做不完 | 12/31 決策點退回固定站位，或改成同屬性共用技能 |
| AI 生成的寵物圖風格不一致、授權不清 | 固定同一個工具和提示詞；確認工具條款；不行就改用簡單造型 |
| 寵物設計多、數值難平衡 | 寵物限 12 種；技能只用 6 種效果模組 |
| 遊戲搶走學習時間 | 寵物經驗值、進化、技能強度都來自答題與學會的單字；每天限 3 場對戰 |
| AI 產生的例句不自然、有錯，或誘答選項也說得通 | 誘答選項由程式規則挑選；自動檢查加人工檢查；不合格的用 Tatoeba 或組員自寫補足 |
| 測試期短，有新奇效應 | 報告時列為限制 |
| 雲端免費方案條件改變，或第一次部署卡關 | 第 5 週前完成部署；保留「一台電腦當伺服器」的做法 |
| 展示場地網路不穩，或封鎖電腦之間的連線 | 帶手機熱點；事先到場測試 |
