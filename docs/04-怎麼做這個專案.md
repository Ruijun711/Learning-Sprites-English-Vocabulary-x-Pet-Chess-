# 學習精靈｜怎麼做這個專案

2026-11-18（依 Brief v3 與 PRD v2 改寫）。會議用。說明系統怎麼運作、工作怎麼拆、先做什麼。細節見 Brief 與 PRD。

## 一句話

用背英文單字來養桌面上的精靈寵物，再讓寵物組隊打自走棋；自己訓練的 AI 預測哪些字快忘了，安排複習。

## 系統怎麼運作

1. 使用者開啟桌面小程式，寵物出現在桌面上（最多 6 隻）
2. 在練習視窗做單字題（英選中、中選英、拼字、例句填空），系統依熟練度換題型
3. 每次作答都存進本機資料庫，同時更新這個字的紀錄；答錯的字進錯題題庫
4. 答對時桌面上的寵物拿經驗值，有機率掉蛋；學會的字夠多時寵物進化，技能也變強
5. 每天第一次開啟有抽考；寵物身上出現符號時有額外題目；抽哪些字由 AI 模型決定
6. 桌面上的 6 隻寵物上傳到對戰伺服器，伺服器配對、算完戰鬥，本機播放；分數進排行榜

```
桌面程式（PySide6）
 ├─ 桌面寵物、系統匣
 └─ 視窗（QWebEngineView）──► 本機 Flask ──► 本機 SQLite
                                  │  └─ 載入 AI 模型
                                  └─────► 對戰伺服器（Flask，雲端）
                                           上傳隊伍／找對手／算戰鬥／排行榜
```

## 現在已經有的東西

`app/learning-spirit.html` 是單一網頁的簡易版原型，已經能玩完整流程：做題、錯題、抽考、額外題目、寵物、掉蛋、進化、對戰、單字紀錄。正式版不是從零開始，而是把原型拆開：

| 原型裡的 | 搬到正式版的 |
| --- | --- |
| 介面（HTML/CSS/JS） | 本機 Flask 提供的網頁，內嵌在 QWebEngineView |
| `localStorage` 的資料 | 本機 SQLite |
| 出題、批改、寵物規則（`record()` 等） | 本機 Flask API |
| `simulate()`、`teamSnapshot()` | 對戰伺服器（改寫成 Python） |
| `makeOpponent()` | 伺服器的「找對手」 |
| `recallP()` 半衰期公式 | 訓練好的 Logistic Regression 模型 |
| `SPRITES`、`art/` | 寵物圖 |

## 工作拆成六塊

| 工作 | 要做的事 | 使用技術 | 人數 |
| --- | --- | --- | --- |
| 桌面程式 | 透明置頂的桌面寵物、對話框、系統匣、視窗管理、內嵌網頁、打包成安裝檔 | Python、PySide6 | 1 |
| 本機後端 | 資料表、出題與批改、熟練度、錯題、抽考、額外題目、經驗值、掉蛋、孵化、進化、每日狀態 | Python、Flask、SQLite | 1 |
| 介面 | 練習、寵物倉庫、單字紀錄、說明與設定；從原型拆出並接上 API | HTML、CSS、JavaScript | 1 |
| 對戰 | 伺服器 4 個 API、戰鬥計算、排陣與 Canvas 回放、排行榜、雲端部署 | Python、Flask、Canvas | 1 |
| AI 模型 | Duolingo 資料清理、特徵、訓練、評估、整合進本機 Flask | Scikit-learn、Pandas | 1 |
| 題庫與實驗 | 300 字字表、屬性分類、AI 例句產生與檢查（Tatoeba 補充）、整合測試、實驗設計與招募、問卷 | Python、試算表 | 1 |

中文意思與例句由六人分攤；寵物的技能與數值由對戰負責人主導、全組一起試玩調整。

## 開發順序

專題期間 11/27 – 1/21，約八週。

| 階段 | 時間 | 目標 |
| --- | --- | --- |
| 1. 打底 | 第 1–2 週 | 字表、AI 產生例句並檢查、資料表、本機 Flask＋練習頁；AI 組員用 Duolingo 資料做出基準 |
| 2. 寵物與桌面 | 第 3 週 | 寵物養成規則、PySide6 桌面寵物上線 |
| 3. 對戰與模型 | 第 4–5 週 | 對戰伺服器、排陣與回放、部署到雲端；模型接上抽考與錯題；**12/31 戰棋決策點** |
| 4. 實驗 | 第 6–7 週 | 交叉實驗兩週、後測；有時間再做發音 |
| 5. 發表準備 | 第 8 週 | 延後測驗、分析、簡報、展示演練 |

原則：
- **原型先用、邊用邊改**：介面和規則都已經在原型裡，優先把它接上真正的後端，不要重寫
- **模型不用等資料**：用 Duolingo 公開資料第 1 週就能開始訓練
- **第 5 週一定要有測試版**：實驗要兩週，晚一週就壓縮到發表準備

## 第一週要完成的事

- [ ] 決定「產品問題討論」裡的六題
- [ ] 確認六人分工
- [ ] 建立 GitHub 專案，所有人能 clone 並開啟原型
- [ ] 定好本機資料表欄位，特別是 `answer_records`（實驗與模型驗證資料）
- [ ] 定好隊伍快照與對戰 API 的格式（沿用原型 `teamSnapshot()`）
- [ ] 選出 300 字並分給六人寫中文意思、屬性；試 2–3 個開源模型產生例句並選定模型
- [ ] AI 組員下載 Duolingo 資料集，跑出基準

## 協作方式

- 程式碼放 GitHub，每人開自己的分支，完成後合併
- 每週開一次會：完成了什麼、卡在哪裡、下週做什麼
- 先約定好 API 格式，前後端可以同時開發
- 遊戲數值集中在一個設定檔（像原型的 `CFG`、`SPECIES`），調整時不用改程式

## 最大的三個風險

| 風險 | 備案 |
| --- | --- |
| 戰棋（移動、找路、技能）做不完 | 原型已有可運作的 `simulate()`，直接改寫成 Python；12/31 還不穩就退回固定站位，或改成同屬性共用技能 |
| PySide6 桌面寵物卡關（透明視窗、點擊穿透、多螢幕） | 第 3 週先做最簡單的置頂小視窗；真的不行就只保留系統匣＋一般視窗，寵物顯示在練習視窗裡 |
| 測試版太晚上線，實驗做不完 | 第 5 週前完成雲端部署；實驗不夠兩週時縮成每組各 5 天，並在報告中說明 |
